{{ _('4. Níveis de Segurança & Persistência') }}

O nível ativo de cada módulo é armazenado no banco de dados individualmente por usuário na tabela security_levels: 

CREATE TABLE security_levels (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    module TEXT NOT NULL,
    level TEXT NOT NULL CHECK(level IN ('low','medium','high','impossible')),
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, module)
);

A troca de nível é realizada através do endpoint seguro POST /level/<module>, garantindo que o progresso seja persistido entre diferentes sessões de navegação.

{{ _('5. Como Criar um Novo Módulo') }}

Para estender o DUNO com um novo laboratório (ex: ssrf), siga o ciclo estruturado em 4 etapas:

  1. Crie o diretório em modules/ssrf/ com routes.py, logic.py e a pasta source/ contendo os 4 arquivos (low.py a impossible.py).
  2. Adicione o slug em VALID_MODULES no arquivo core/security_levels.py.
  3. Registre o Blueprint em app/__init__.py na função _register_blueprints.
  4. Crie o template correspondente em templates/modules/ssrf.html herdando de base.html e incluindo o seletor _level_switch.html.

{{ _('6. Testes & Verificação') }}

O projeto possui testes automatizados cobrindo cada nível de segurança de cada módulo, garantindo que o nível low seja realmente explorável e o nível impossible seja estritamente impenetrável: 

# Executa a suíte de testes com pytest dentro do container
sudo docker-compose exec duno-app pytest -v

{{ _('7. Reset Global do Banco') }}

{{ _('Como os laboratórios sofrem ataques reais de injeção SQL, inserção de scripts no guestbook e manipulação de credenciais, o DUNO possui uma rotina de reset idempotente.') }}

O reset recria todas as tabelas e dados padrão (seed) executando POST /reset, disponível a qualquer momento no Menu do Usuário na barra de navegação.
