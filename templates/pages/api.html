{{ _('Authentication') }}

{{ _('Mecanismos de autenticação de API implementados de forma deficiente permitem que atacantes comprometam tokens de autenticação ou explorem falhas de implementação para assumir a identidade de outros usuários.') }}

Vulnerabilidade: Tokens estáticos sem expiração, falta de revogação e cabeçalhos desprotegidos.
Mitigação: OAuth2 com fluxos bem definidos, PKCE, rotação de tokens e validação rigorosa de assinatura.
{{ _('JWT SEC') }}

{{ _('JSON Web Tokens (JWT)') }}

Tokens JWT assinados com chaves fracas (vulneráveis a ataques de dicionário offline), aceitação do algoritmo none ou manipulação de cabeçalhos de chave (kid) para forjar claims sem permissão.

Vulnerabilidade: Modificação de claims de privilégio (ex: "role": "admin") aceitas pelo backend.
Mitigação: Algoritmos assimétricos (RS256/ES256), chaves fortes gerenciadas em HSM/KMS e validação estrita do payload.
{{ _('API01 — TOP 1') }}

{{ _('BOLA / IDOR') }}

Broken Object Level Authorization é a vulnerabilidade mais severa em APIs REST. A API recebe o identificador do recurso (ex: user_id) e não valida se o usuário autenticado é o legítimo proprietário daquele registro.

No DUNO: O módulo #20 API Security simula exatamente essa extração através de /api_security?user_id=X.
Mitigação: Políticas de autorização a nível de objeto no banco: WHERE id = ? AND owner_id = current_user.id.
{{ _('API06') }}

{{ _('Mass Assignment') }}

Ocorre quando o framework de backend faz o bind automático de todos os campos do payload JSON para o modelo de dados, permitindo que atacantes sobrescrevam propriedades protegidas (ex: is_admin, balance, status).

No DUNO: O módulo #19 Mass Assignment demonstra como injetar permissões administrativas via requisição POST.
Mitigação: Uso de DTOs (Data Transfer Objects) e schemas com whitelist estrita de campos aceitos.
{{ _('API04') }}

{{ _('Rate Limiting & Throttling') }}

{{ _('Ausência de restrições quanto ao número de requisições que um cliente pode disparar em determinado intervalo de tempo. Viabiliza ataques de força bruta, raspagem de dados em massa (scraping) e negação de serviço.') }}

Vulnerabilidade: Enumeração automatizada de códigos de cupom, IDs de clientes ou senhas de acesso.
Mitigação: Algoritmos de Token Bucket ou Leaky Bucket implementados via API Gateway ou Redis.
{{ _('API09') }}

{{ _('Improper Versioning') }}

APIs evoluem para novas versões mais seguras (ex: /v2), mas endpoints legados (/v1) permanecem ativos em produção sem os patches de segurança adequados, tornando-se portas dos fundos para atacantes.

No DUNO: O módulo #18 API Versioning permite alternar entre versões de API e extrair dados sem autenticação.
Mitigação: Políticas rigorosas de deprecation, desativação de versões legadas e inventário contínuo de endpoints.
{{ _('API03') }}

{{ _('Secrets & Data Leakage') }}

{{ _('Respostas de API que expõem inadvertidamente segredos operacionais, tokens de provedores externos, campos confidenciais de usuários (CPF, senhas hasheadas) ou detalhes internos de depuração do sistema.') }}

Vulnerabilidade: Desenvolvedor confia que o front-end ocultará os dados confidenciais do usuário.
Mitigação: Serializadores explícitos no servidor, sanitização de logs e exclusão estrita de campos sensíveis.
