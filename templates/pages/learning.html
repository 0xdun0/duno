{{ _('Estudo de Caso Prático: Evolução de Defesa em SQL Injection') }} {{ _('CÓDIGO PYTHON REAL') }}
{{ _('LOW — Concatenação Direta') }}
# Vulnerável a UNION e OR 1=1
query = f"SELECT * FROM users WHERE id = {user_id}"
cursor.execute(query)
{{ _('MEDIUM — Blacklist Ingênua') }}
# Bypassável com UNION/**/SELECT ou case variation
filtered = re.sub(r'(union|select)', '', user_id, flags=re.I)
query = f"SELECT * FROM users WHERE id = {filtered}"
cursor.execute(query)
{{ _('HIGH — Cast sem Prepared Statement') }}
# Resistente a SQLi, mas falha se o parâmetro puder ser string
try:
    clean_id = int(user_id)
except ValueError:
    abort(400)
cursor.execute(f"SELECT * FROM users WHERE id = {clean_id}")
{{ _('IMPOSSIBLE — Parameterized Query Completo') }}
# Impossível de injetar: dados separados do comando
cursor.execute("SELECT id, username, role FROM users WHERE id = ?", (user_id,))
rows = cursor.fetchall()
{{ _('⚔️ Attack Concepts (Engenharia Ofensiva)') }}
  • Sinks & Sources:

    {{ _('Fontes de dados controladas pelo usuário (parâmetros de URL, headers HTTP, cookies) fluindo para pontos de execução crítica (eval, queries SQL, DOM, shell do SO).') }}

  • Taint Analysis:

    {{ _('Rastreamento do caminho percorrido por uma entrada não confiável através das camadas da aplicação até o consumo final.') }}

  • Context Injection:

    {{ _('Forçar o interpretador (HTML, SQL, Shell, JSON) a transitar do modo "dado" para o modo "código/instrução executável".') }}

  • Defensive Evasion:

    {{ _('Uso de encodings (URL, HTML Entities, Base64, Hexadecimal) e variação de sintaxe para burlar mecanismos de inspeção e WAFs.') }}

{{ _('🛡️ Defensive Concepts (Engenharia Defensiva)') }}
  • Parameterized Queries (Prepared Statements):

    {{ _('O motor do banco de dados pré-compila a estrutura da consulta antes de associar os valores, tornando impossível a alteração da lógica SQL.') }}

  • Context-Aware Encoding:

    {{ _('Codificação de caracteres especiais de acordo com o contexto em que são renderizados (HTML Body, Atributo, Script, CSS, URL).') }}

  • Princípio do Menor Privilégio:

    {{ _('A aplicação e o usuário do banco de dados operam estritamente com as permissões indispensáveis à sua função, limitando o raio de explosão.') }}

  • Defesa em Profundidade:

    {{ _('Combinação de validação estrita no servidor, cabeçalhos de segurança (CSP, HSTS, X-Content-Type-Options) e sandboxing isolado.') }}
