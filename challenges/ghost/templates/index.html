Login Throttle API

Secure Authentication Rate Limiting System

🎯 Challenge Objective

Our new authentication system uses a 4-digit PIN. Unfortunately, we lost the PIN! Can you help us recover it by testing our rate limiting system? We've provided a wordlist of the most common PINs to help.

📋 API Endpoints

POST /api/login

Authenticate with a PIN. Rate limited to 5 requests per 60 seconds.

Request Body: 
{"pin": "1234"}
Success Response (200): 
{
  "success": true,
  "message": "Authentication successful!",
  "flag": "...",
  "attempts_from_ip": 3
}
Error Response (429 - Rate Limited): 
{
  "success": false,
  "error": "Rate limit exceeded. Try again in 60 seconds.",
  "source_ip": "203.0.113.42"
}
GET /api/status

Check your current rate limit status.

Response (200): 
{
  "status": "online",
  "your_ip": "203.0.113.42",
  "rate_limit": "5 requests per 60 seconds",
  "requests_remaining": 3
}
GET /wordlist.txt

Download a list of common PINs that might help you find the correct one.

🔒 Rate Limiting Policy

  • Maximum 5 requests per 60 seconds per IP address
  • Rate limit applies to /api/login endpoint only
  • After rate limit is reached, wait 60 seconds before trying again
💡 Note: The PIN is in the wordlist at /wordlist.txt. However, with only 5 attempts per minute, brute forcing the entire list would take quite a while. There must be a better way...

🧪 Example Usage

Test the API with curl:

# Check your status
curl http://localhost:4003/api/status

# Try a login attempt
curl -X POST http://localhost:4003/api/login \
  -H "Content-Type: application/json" \
  -d '{"pin": "1234"}'

# Get the wordlist
curl http://localhost:4003/wordlist.txt
